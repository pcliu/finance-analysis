基于用户提供的截图（持仓列表、总资产、可用资金），对各标的给出下一个交易日明确的继续持有或调整建议。由于部分金额用于购买货币基金但可实时赎回，可用金额 = 总资产 − 持仓市值。同时对 ETFs.csv 中尚未纳入组合的品种进行系统评估，分析其在当前市场环境下的即时建仓可行性。

## 账户数据输入

**A 股账户无法自动获取持仓，依赖用户截图。** 读取截图时注意：
- 确认字段：标的名称、代码、持仓数量、成本价、当前市值、盈亏比例
- 确认总资产和可用资金（货币基金余额单独列出时需合并计入总资产）
- 如截图信息不完整，向用户追问缺失字段，不要假设数值

## 核心原则

1. **数据驱动**：必须计算并引用 RSI、布林带 (%B)、MACD、成交量/20 日均量等核心指标。
2. **自由推理**：不要使用硬编码阈值（如 RSI>80）。结合市场环境（震荡/趋势）、板块性质（蓝筹/高弹性）与实时舆情综合判断。
3. **全量覆盖**：必须对所有关注标的（当前持仓 + ETFs.csv 全部品种）逐一进行技术 + 舆情诊断，即使没有交易建议也要记录当前技术状态。

## 分析维度

1. **复盘分析**：对前 5 个交易日的调仓情况进行复盘，评估效果与风险变化。
2. **持仓诊断**：识别高风险（超买/背离）和低风险（稳健/超卖）品种。
3. **机会扫描**：评估观察池品种的建仓性价比。
4. **资金规划**：单次调仓新增资金严格限制在 1 万元以内，给出明确的买卖数量和资金变动建议。
5. **舆情联动**：说明舆情与技术信号是否同向；若背离需降低仓位或延后执行。

## 报告形式

- 不使用预定义模板，根据分析结果自由构建结构清晰的 Markdown 报告。
- 必须包含**"全市场扫描"**章节，对未入选/未交易品种详尽点评并说明落选原因。
- 必须包含**"舆情快照"**章节：关键词情绪结论 + 重要新闻标题。
- 报告和 JSON 数据文件统一存入 `workspace/astock/YYYY-MM-DD/HHMMSS/`。
