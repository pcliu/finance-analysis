通过 Moomoo OpenD API 自动获取账户持仓、资金、订单状态和关注列表，结合技术指标和舆情分析，对各标的给出今日明确的继续持有或调整建议，并对「USStocks」关注分组中尚未纳入组合的品种评估即时建仓可行性。

## 账户数据获取（自动化）

使用 `moomoo-trading` skill 自动拉取以下数据，**无需用户手动输入**：

```python
from scripts import get_account_info, get_positions, get_order_list
import moomoo as ft

# 账户资金
account = get_account_info(trading_env='REAL')

# 当前持仓
positions = get_positions(trading_env='REAL')

# 今日订单状态（用于复盘）
orders = get_order_list(trading_env='REAL')

# 关注列表观察池（动态读取，与 moomoo App 同步）
ctx = ft.OpenQuoteContext(host='127.0.0.1', port=11111)
ret, watchlist = ctx.get_user_security(group_name='USStocks')
ctx.close()
# watchlist 包含列：code, name, stock_type
```

> **注意：** 交易密码从项目根目录 `.env.local` 的 `MOOMOO_TRADE_PASSWORD` 读取，连接参数同样来自该文件。

## 可投资金额计算规则

> 用户资金大部分持有基金，买股票时可从基金实时赎回。**不能用现金余额代表可投资金额。**

```
可投资金额 = 总资产 (total_assets) - 股票持仓市值 (market_val)
```

- `total_assets`：账户总资产（含现金 + 基金 + 股票市值）
- `market_val`：当前股票持仓市值
- 差值即为可随时调配的资金（现金 + 可赎回基金）

报告"账户快照"章节必须展示此计算过程，**禁止将可用资金仅写为现金余额**。

## 价格时段与实时性规则（关键）

美股有 4 个交易时段（美东时间）：

| Session | 时段 ET | moomoo Session 枚举 |
|---|---|---|
| Pre-Market | 04:00–09:30 | `ETH` 或 `ALL` |
| RTH | 09:30–16:00 | `RTH` |
| After-Hours | 16:00–20:00 | `ETH` 或 `ALL` |
| Overnight | 20:00–04:00 | `OVERNIGHT` 或 `ALL` |

### 三种价格的区分（必须分清）

| 价格 | 来源字段 | 含义 |
|---|---|---|
| RTH 收盘价 | `realtime_quote.prev_close_price` | 上个常规时段收盘价（最稳定锚点） |
| 上日盘后最终价 | `position.nominal_price` | 持仓信息中显示的"上一笔成交价"。在盘前查看时，这通常是**上个交易日盘后扩展时段最后一笔**，**不是当前盘前实时价** |
| 当前实时价 | `realtime_quote.last_price`（含 `update_time`） | 当下盘前/RTH/盘后的最新成交价，是真正的"可成交参考价" |

**强制规则：**
1. 一律使用 `realtime_quote.last_price`（标注 `update_time`）作为"当前价"——它已包含盘前/盘中/盘后所有时段的最新成交价，**不要使用 `position.nominal_price`**。
2. 浮盈亏一律按 `(realtime.last_price - cost_price) × qty` 计算，不再呈现 moomoo App 的显示版盈亏。

### 下单 Session 设置

- 默认订单允许在盘前/盘中/盘后撮合：`fill_outside_rth=True`、`session=ft.Session.ETH`
- 盘前/盘后/夜盘**仅支持限价单**（`OrderType.NORMAL`）；`MARKET` API 在扩展时段会被拒绝
- 24-hour 全时段订单使用 `session=ft.Session.ALL`

## 核心原则

### 不可违反的硬规则

1. **数据驱动**：必须计算并引用 RSI、布林带 (%B)、MACD、成交量/20 日均量等核心指标，不能只基于主观叙事给出交易建议。
2. **数据新鲜度校验**：所有用于决策的数据（K 线、技术指标、实时行情、账户快照、舆情/新闻）必须在使用前校验时间戳。K 线 / 技术指标距当前交易日间隔 > 5 个交易日，实时行情 > 30 分钟，账户/订单快照 > 当日，舆情 > 7 天，均视为过期，必须重新拉取或中止分析并报错，禁止用过期数据生成建议。**当前价一律以 `realtime_quote.last_price` 为准**，不使用 `position.nominal_price`（参见上文"价格时段与实时性规则"）。
3. **账户优先**：先评估账户整体风险、股票仓位、可投资金额、行业集中度和近期订单，再讨论单只股票。
4. **全量覆盖**：必须对所有关注标的（当前持仓 + USStocks 关注列表全部品种）逐一进行技术 + 舆情诊断，即使结论是观望也要说明原因。
5. **不为交易而交易**：当赔率不足、信号冲突、重大事件临近或现金更有价值时，明确给出“观望/不操作”建议。
6. **订单安全**：下单前必须打印完整订单摘要（标的、方向、数量、价格、预估金额），并在 chat 中获得用户明确确认后方可执行真实交易。

### 交易决策框架

1. **自由推理，但有纪律**：不使用机械硬阈值（如 RSI > 70 必卖），结合趋势阶段、波动率、板块轮动、估值/基本面、事件风险和舆情共同判断。
2. **先组合，后个股**：避免所有仓位集中在同一叙事或高度相关板块（例如 AI 半导体）。若多个标的依赖同一逻辑，必须控制组合总暴露。
3. **仓位优先于观点**：看好不等于重仓。每个买入/加仓建议都要说明建议仓位、分批方式、预估成本和最大风险。
4. **顺势但不盲目追高**：强趋势可以容忍偏高指标，但若价格远离均线、缩量上涨或临近事件窗口，应降低追高建议优先级。
5. **事件风险降权**：财报、FOMC、CPI、就业数据、重大监管/诉讼、产品发布前，除非赔率极佳，否则避免新开重仓。
6. **区分交易类型**：每个建议必须标注属于短线交易、波段配置、长期核心仓位、防御对冲或观察等待。
7. **买入必须有失效条件**：每个建仓或加仓建议都要写明判断失效条件，以及触发后应止损、减仓、暂停加仓或重新评估。
8. **现金也是仓位**：当市场整体风险偏高或可选标的赔率一般时，保留现金/基金仓位是有效选择。

### 仓位参考刻度（非硬阈值，根据市场环境调整）

以下数字作为推理时的对照锚点，不是机械红线。当突破这些刻度时必须在报告中显式说明理由（例如强趋势中允许更高单标的占比，或防御期间提高现金缓冲）。

- 单标的市值 ≤ 股票仓位的 30–40%
- 单一叙事 / 板块 ≤ 股票仓位的 50%
- 单次新增资金 ≤ 可投资金额的 25%
- 现金 + 可赎回基金缓冲 ≥ 总资产的 20%

## 分析维度

1. **账户快照**：展示总资产、股票持仓市值、可投资金额、现金/基金可调配资金、当前股票仓位比例。
2. **组合风险**：识别行业集中度、单一标的集中度、同一宏观叙事暴露、近期重大事件风险和市场整体风险。
3. **复盘分析**：结合今日订单状态，对前 5 个交易日的调仓情况进行复盘，说明执行效果、错过机会和风险变化。
4. **持仓诊断**：识别高风险（超买/背离/事件风险/趋势破位）和低风险（稳健/回调到位/防御属性）品种。
5. **机会扫描**：评估观察池品种的建仓性价比，明确“可买、等待、回避”的原因。
6. **资金规划**：给出明确的买卖数量、分批节奏、预估成本（USD）、交易后股票仓位比例和剩余可投资金额。
7. **舆情联动**：说明舆情与技术信号是否同向；若背离需降低仓位、延后执行或只做观察。
8. **退出计划**：每个交易建议必须包含止损/减仓/重新评估条件，不能只写买入理由。

## 报告形式

- 不使用预定义模板，根据分析结果自由构建结构清晰的 Markdown 报告。
- 必须包含**"账户快照"**章节：总资产、持仓市值、可用资金（USD）。
- 必须包含**"组合风险"**章节：股票仓位、行业集中度、事件风险、现金/基金保留是否合理。
- 必须包含**"全市场扫描"**章节，对未入选/未交易品种详尽点评并说明落选原因。
- 必须包含**"舆情快照"**章节：关键词情绪结论 + 重要新闻标题。
- 必须包含**"调仓建议"**章节：每条建议包含标的、方向、交易类型、数量、参考价、预估成本、分批方式、理由、风险、失效条件。
- 若没有合适交易，必须明确写出“不操作”的理由和下一次需要观察的触发条件。
- 报告和 JSON 数据文件统一存入 `workspace/us/YYYY-MM-DD/HHMMSS/`。
